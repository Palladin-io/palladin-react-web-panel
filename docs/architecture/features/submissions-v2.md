# Additive Agent submission plaintext v2

Contract: [palladin-protocol v2 draft](https://github.com/Palladin-io/palladin-protocol/blob/feat/cvt-641-submission-v2/contracts/agent-submission/v2/README.md). [Protocol PR #19](https://github.com/Palladin-io/palladin-protocol/pull/19) coordinates the draft; it is not a published protocol release.

Browser capture submissions may use `palladin.agent-submission-payload.v2` inside the existing signed and encrypted v1 transport. Envelope schema, identity, key wrapping, signature domain, AAD, and the 32768-byte plaintext limit remain unchanged. Frozen v1 payload rules and fixtures remain supported.

Only Credential and Key Entries are supported. V2 adds optional `description` and `content.customFields`. A custom field is `{id, type, value, label?}`; IDs are canonical `custom:<lowercase UUID>`. Supported types are `text`, `multiline`, `concealed`, and `totp`. The reviewed scope excludes Script, CreditCard, built-in TOTP, and sign-in-method custom fields.

New submissions require a label and the existing required content (Credential username/password, Key value). Each custom field requires a label. Update submissions may propose any subset of content, label, or description; a proposal with no changes is rejected. An absent property preserves the current value. Empty values explicitly clear string content; labels and Credential URLs cannot be empty. Custom fields are stable-ID upserts, never deletions. An existing field retains its label when the proposal omits one. A new ID requires a label at merge time. Changing an existing field's type is rejected. Saving an update as a new Entry additionally requires all new-entry content and custom labels; incomplete sparse updates cannot use that fallback.

Custom fields are limited to 64, unique IDs, 128-byte labels, and 16384-byte string values. TOTP values require canonical uppercase unpadded Base32 secret up to 1024 bytes (complete bytes and zero unused trailing bits), SHA1/SHA256/SHA512, 6/8 digits, and a period of 15–120 seconds; issuer/account are optional nullable strings up to 1024 bytes. Description/notes allow 8192 bytes, username 1024, password 4096, Key value 16384, URL 2048, and Entry label 256. Strings must be well-formed NFC Unicode; secrets are never normalized.

The review displays description, all proposed built-in values, custom IDs, proposed labels, types, values, and every TOTP parameter. Concealed values and TOTP seeds use reveal controls; newline-bearing custom strings use a multiline presentation without altering the proposal. Approval remains an explicit member action. Native browser capture supplies content; the agent may provide literal Entry name and description. The panel authenticates and validates the encrypted proposal and does not trust page messages.

Approval merges against the exact signed target revision. Existing permissions and omitted fields remain unchanged. New custom fields start at `never`, including on new Entries; default Agent grants therefore do not expose them. The existing canonical update producer refreshes grants for changed Entries. Current values are not fetched merely for preview: omitted custom labels are displayed as retained, with the stable ID identifying the field.

Tests cover opening v1 and v2 using the same authenticated transport, malformed v2 inputs, sparse merging and permission preservation, canonical Entry round trips, and review of all supported proposed fields without automatic approval. No production submissions are created by these tests.
